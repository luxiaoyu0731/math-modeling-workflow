# 从任务到论文

## 可恢复的执行循环

每轮读取实际文件 → 判断当前缺口 → 明确本轮产物和验收 → 完成计算或文档工作 → 核验 → 记录交接。恢复时读取状态和证据，不根据聊天记忆猜测已完成工作。

## 阶段

| 阶段 | 核心问题 | 验收依据 |
|---|---|---|
| G0 启动 | 任务范围、输入及规则是否明确？ | 输入审计、任务档案 |
| G1 读题 | 每个问题到底要求什么？ | 问题合同、变量单位、输出映射 |
| G2 证据 | 数据和参数能否使用？ | 来源、质量、假设与验证计划 |
| G3 建模 | 为什么选择这个模型？ | 基线比较、模型卡、推导与边界 |
| G4 求解 | 实际运行得到了什么？ | 代码映射、运行记录、结果文件 |
| G5 验证 | 哪些结论有足够证据？ | 对照、误差、稳健性及适用范围 |
| G6 制图 | 哪幅图帮助理解或支撑结论？ | 图卡、ImageGen记录、图像检查 |
| G7 写作 | 是否形成完整、连贯的回答？ | 论文、反向大纲、主张与引用追踪 |
| G8 终审 | 最终文件是否与证据一致？ | 实际成品检查、清单及未解问题 |
| G9 复盘 | 哪些经验可用于新任务？ | 去掉案例参数的经验总结 |

图形在G3随模型一起规划，G6集中核验；写作可先搭结构，未经验证的结果不可冒充定论。检查发现上游错误时回退对应阶段，已完成的独立工作保留。

## 深度与范围

完整流程用于完整交付。只问模型审查、图形修订或论文排版时，处理相应阶段及必要依赖，不强行重新求解全部问题。需要用户决定的范围或重大取舍应明确提出；可逆、已授权的工作持续推进。

## 论文表达

每个子问题形成“问题—选择理由—假设与推导—求解—结果—验证—回答”的链条。强调公式含义、适用条件和图文对应，求解细节保留到足以复现。摘要写在结果稳定之后。篇幅通过必要分析自然形成，不规定统一页数或图数。

## 变更与交付

上游数据、模型、参数或评价器变更，要使依赖的结果、图和论文结论失效并重新检验。排版微调只需检查受影响的成品。完整交付包括源稿、最终文档、计算/制图依据、验证记录及明确限制；是否对外提交由用户授权决定。
